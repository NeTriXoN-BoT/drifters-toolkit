# Third-party components

Runtime application code is C++17 with a bundled local HTML/CSS/JavaScript interface. Windows hosts it in Microsoft Edge WebView2; Linux uses Qt WebEngine with a restricted Qt WebChannel. No remote fonts, scripts or CDN UI libraries are used.

The runtime downloads collect component copyright notices and licence texts in one `LICENSES.txt` beside the programs. Licence filenames below identify sections in that file; the matching technical source materials retain the original notice files as well.

Microsoft Edge WebView2 Evergreen Runtime is installed separately and serviced by Microsoft. The DLL distributed with this app is the official x64 WebView2 loader from the pinned NuGet package. Downloaded mods remain independent packages with their original authorship and permissions.

Dependency download URLs and SHA-256 values are recorded in `scripts/dependencies.lock.json`. The compiler archive is a local build dependency, not part of the portable app or source archive.

The local archive decoders have their own six-source lock, `scripts/archive_sources_lock.json`, and reproducible static build recipe, `scripts/bootstrap_archive.py`. All six original upstream archives are retained intact in the technical source review and matching Linux source companion. The small runtime downloads contain the native programs and licence notices, with no external archive command, Python runtime or new archive DLL. ZIP/ZIPX, 7z, RAR/RAR5, TAR/PAX, CAB, CPIO, LHA/LZH and AR readers are explicitly registered; gzip, bzip2, XZ/LZMA, lzip, Zstandard, LZ4 and compress filters are built in. Features still depend on the actual compression method used inside a format. Password-protected content, split-volume archives, links, sparse/special files and self-executing installers are not import targets.

The archive build recipe explicitly limits libarchive individual heap allocations and LZMA decoder dictionaries to 128 MiB. This is not a 128 MiB aggregate process-memory promise. The shared importer separately bounds source/file size, entry count and expanded data, rejects unsafe paths and never calls the library's disk extractor or external helper. Miniz remains independent for authenticated update/catalog ZIPs and private backup formats.

The same 1,024-file/folder limit is enforced inside the 7z reader before metadata arrays are allocated. Coder input/output stream counts are limited to sixteen, and coder properties to 4,096 bytes, before associated parsing or allocation. These reproducible build-only changes are explicit exact-match edits in the source recipe and fail closed if the pinned upstream text changes.

The statically linked Windows runtime notices ship separately from the compiler. The MinGW-w64 notice comes from the exact runtime commit selected by the pinned llvm-mingw build recipe, and the LLVM notice matches the pinned compiler archive. These notices are retained unmodified; their hashes and source URLs are in the dependency lock file.

The bundled `ui/assets/seasonal-emoji.svg` arranges eighteen Noto Emoji SVG originals into a six-by-three sprite, with local ID prefixes and clipped cells. Every source file is pinned by commit, SHA-256 and size in `scripts/dependencies.lock.json`; `scripts/build_seasonal_emoji.py` reproduces the sprite and rejects active content or external references. Google's SVG copyright notice and the complete Apache2.0 licence ship in LICENSES.txt. Images avoid color-font painting differences between WebView2 and Linux Qt WebEngine. No system font installation or runtime image download is needed. The clean technical source includes the original SVGs and build helper.

Linux targets one universal AppImage for x86-64 distributions; there are no distribution-specific Linux packages. The 1.0.9 recipe requires the original official Qt 6.11.3 base SDK, ICU 73.2 and a verified OpenSSL 3.5.9 source build, together with the other libraries the toolkit and Qt WebEngine need from Debian 12 packages. WebEngine must be rebuilt from the complete Qt 6.11.3 source archive with all five recorded security layers: the original 24 vendor changes and Aura adapter, the four-repair followup, the 30 October incremental repairs, the residual/vendor batch, and the 1 November vendor followup. Their original locks and provenance files stay unchanged. The latest build and staging gate is `QTWEBENGINE-SECURITY-VENDOR-FOLLOWUP-PROVENANCE.json`; it binds the inherited proof chain, exact source and recipe inputs, and actual rebuilt outputs. The requirements are documented in `docs/QT_WEBENGINE_SECURITY_2026-10-26.md`, `docs/QT_WEBENGINE_SECURITY_2026-10-28.md`, `docs/QT_WEBENGINE_SECURITY_2026-10-30.md`, `docs/QT_WEBENGINE_SECURITY_2026-10-30-RESIDUAL.md` and `docs/QT_WEBENGINE_SECURITY_2026-11-01-VENDOR-FOLLOWUP.md`. This inventory alone does not establish that a patched Linux binary has completed validation. Frozen releases retain their original inputs.

The final 30 October source batch retains seven newer official Qt vendor exports through commit `43bcb1ece119814c1be448629ba0bd751b51ec7d` and the public-associated repairs for fourteen further advisory entries. One vendor repair is already present in the predecessor source; the ANGLE Metal changes are outside the Linux compilation target. The Brotli roll changes the bundled source from 1.0.9 revision `9801a2c5d6c67c467ffad676ac301379bb877fc3` to 1.2.0 revision `cfa184a997ac19454d5a3ae97f6d600aac2445a6`. Its MIT licence text is unchanged. The revised `README.chromium`, build description and new source files form part of the matching source materials, and Chromium notices must be generated from that source. These are scoped backports on the Chromium 140 base, not a major-version upgrade or a claim of complete current Chrome security parity. Windows continues to use the separately serviced WebView2 Evergreen runtime.

The Linux rebuild also requires a separately identified compatibility adapter for the Aura weak-pointer dependency in Qt's CVE-2026-19142 backport. It is derived from Google's [M144-LTS API change](https://chromium.googlesource.com/chromium/src/+/c57a349825ed93a8ac373519fb7da5319fb75335) and the [original capture-window security change](https://chromium.googlesource.com/chromium/src/+/5c2010f1a7ea14ead6d4a9848cce9f783ddd9fc1). The source lock identifies this as a toolkit compatibility adaptation and retains both upstream reference patches, the adapter and exact before/final source hashes. The original 24 Qt patches remain unchanged.

Debian 12 is only the build baseline. The AppImage needs glibc 2.35 or newer and takes only the C/C++ runtime, graphics drivers, libexpat and fontconfig from the host, so fonts follow the system's own font configuration; bundled libraries make it independent of the host's own Qt, Chromium or OpenSSL. `LICENSES.txt` includes each bundled library's copyright and licence. `DEPENDENCY-SOURCES.json` records the official Qt archives, WebEngine security proof, OpenSSL source/build proof and each bundled Debian package's exact source version; `APPIMAGE_MANIFEST.json` identifies the AppImage runtime and matching source companion.

**Qt notice for the Linux application:** this program uses Qt libraries, copyright The Qt Company Ltd. and other contributors, under the GNU Lesser General Public License version 3. Qt and its use are covered by that license. The Linux download includes the complete `GNU-LGPL-3.0.txt` and `GNU-GPL-3.0.txt` documents as sections of `LICENSES.txt`. These are the unmodified license copies in Qt 6.11.2 source commit `ef55f427f2c8b410d34f8a7681020a3000cf6866`; exact URLs, sizes and SHA-256 values are in the dependency lock file. They describe the library terms and do not label all application code as GPL.

The bundled libraries stay dynamically linked inside the AppImage and can be replaced. The `LIBRARY_REPLACEMENT.txt` section of `LICENSES.txt` explains how to extract the AppImage, rebuild the application so it accepts modified interface-compatible LGPL libraries, and repackage it. Reverse engineering needed to debug modifications to LGPL libraries is not restricted. The source-materials tooling requires the exact Qt modules, ICU, OpenSSL source, Debian package sources with their patches, AppImage runtime and application build/replacement materials for the matching companion. Source distribution remains subject to the current release review; this inventory does not establish that a companion has been published. See the [Qt LGPL guidance](https://www.qt.io/development/open-source-lgpl-obligations) and the included license texts.

The bundled libsecret and GLib libraries use LGPL 2.1-or-later terms. The `GNU-LGPL-2.1.txt` section of `LICENSES.txt` includes the unmodified GNU text in official libsecret 0.21.8.2 commit `4941c2f3088eb0ea4a180737b02e22320b8ff7a7`, with its source URL, 26,529-byte size and SHA-256 pin in the lock file. The replacement and debugging rights described above also apply to these libraries.

Bundled libraries do not update with the operating system. Security fixes in Qt WebEngine (Chromium), OpenSSL or another bundled library reach users only through a new AppImage release, so the AppImage must be rebuilt when those projects publish fixes; see `docs/AUDIT_DEPENDENCIES.md` in the review materials.
